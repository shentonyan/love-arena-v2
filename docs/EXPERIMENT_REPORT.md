# 爱语擂台（Love-Language Arena）实验记录

> 日期：2026-09-22　硬件：i7-14700KF + RTX 5070 12GB，Windows 11，Ollama 0.34.2
> 状态：**工作流验证已完成；人工金标准尚未采集。** 本文所有“判官通过验证”的结论都基于 Claude（LLM）的标注，不是人工标注，只能说明流程可用，不能当作研究结论。

## 1. 要回答的问题

用三个本地模型（gemma4:26b、qwen2.5:7b、llama3.1:8b）把带恨语的句子改写成爱语，再让它们互相评审：

- **RQ1**：本地 LLM 判官能否在各维度上替代人工判断？
- **RQ2**：三个模型的爱语改写质量能否区分？
- **RQ3**：判官是否偏爱自己的改写？

最初的想法是用 TypeSafe 的 Jev（一个输出类型化判定和概率的模型）做判官。由于没有 API，改为在 Ollama 上用 logprobs 自行实现 Jev 的三种原语（Choice / Score / Noul），见 `jev_local.py`。

## 2. 设计与文献依据

| 设计 | 依据 |
|---|---|
| 三个不同家族的模型组成评审团 | Verga et al. 2024（PoLL） |
| 全交叉判定（包括自评），再用线性模型扣除判官宽严与自偏好 | Panickssery et al. 2024；多面 Rasch 模型的线性近似（Linacre 1989） |
| 判官只输出一个标记，按 token 概率加权 | G-Eval（Liu et al. 2023） |
| 量表正序、倒序各问一次；陈述与否定各问一次 | 位置偏差（Zheng et al. 2023；Wang et al. 2023） |
| 每个判官单独做 Platt 校准，报告留一法 Brier | 后训练模型校准度差（OpenAI 2023；Kadavath et al. 2022） |
| 主指标 J = 去恨语 × 诚实 × 流畅（相乘） | TextDetox / ParaDetox |
| “诚实”作为硬门槛：改写不能违背原意 | Ziems et al. 2022（positive reframing）；PoL“诚实是一切爱语的基础” |
| 判官必须先通过人工验证才能使用 | Chiang & Lee 2023；Bavaresco et al. 2024 |
| 开发集调优、留出集验证 | 防止对验证集过拟合 |

“恨语”是 PoL 的概念，不等于去毒研究里的 toxicity，也不是 hate speech。本实验借用这些研究的方法，不借用它们的概念。

## 3. 流程

```
generate（60 句 × 3 模型 × 2 次采样 = 360 条改写）
   → annotate（开发集 42 条，按模型分层，盲评）
   → judge（全交叉：3 判官 × 360 条 × 5 维度）
   → tune（开发集上为每个 判官×维度 选提示词变体）
   → judge --tuned（用选中的变体重判）
   → validate --set holdout（留出集 42 条，句子不与开发集重叠）
   → analyze（扣除判官宽严与自偏好，J 分，句子级 cluster bootstrap 2000 次）
   → pairs（只有每个核心维度都有 ≥2 个判官通过验证才产出偏好对）
```

## 4. 迭代过程

| 版本 | 做了什么 | 发现的问题 |
|---|---|---|
| v0.1 | 三模型改写，另外两个模型交叉打分 | 对照文献自查，发现 7 处缺陷，其中最严重的是评审面板不平衡：每个选手由不同的两位判官打分，判官宽严混进了选手分数；此外判官没有和人工对照，概率没有校准 |
| v0.2 | 全交叉、去位置偏差、Platt 校准、J 相乘、bootstrap、预注册 | 真实判定跑完后，诊断发现判官之间一致性很低（见 5.1） |
| v0.2 修复 | 用 Claude 标注测试工作流 | 暴露两个 bug：单判官维度丢失自评格；Platt 校准不收敛（Brier 0.54 反而变成 0.90）。都已修复 |
| v0.3 | 提示词变体 + 开发集调优 + 留出集验证；并发请求 | 调优在开发集上的微小提升不能迁移到留出集（见 5.3） |

## 5. 结果

### 5.1 判官诊断（v0.2，原版提示词，360 条全部判定）

| 维度 | gemma 均值/标准差 | qwen 均值/标准差 | llama 均值/标准差 | 判官两两相关 ρ |
|---|---|---|---|---|
| 恨语残留（0–3） | 0.08 / 0.32 | 1.43 / 0.24 | 1.14 / 0.14 | 0.20 – 0.48 |
| 诚实（概率） | 0.10 / 0.21 | 0.12 / 0.19 | 0.89 / 0.08 | gemma–qwen 0.67；与 llama ≈ 0 |

- **llama3.1:8b 几乎没有区分力**：各维度标准差都只有 0.08–0.18，60 句里 50 句是中文。
- **qwen 和 llama 在量表题上按位置作答**：量表正序、倒序各问一次，一个总选第二个位置的模型会得到 (1 + 2) / 2 = 1.5 分，不管内容是什么。qwen 在恨语残留上均值 1.43、标准差 0.24，正符合这个特征；而这些改写 gemma 判为完全没有残留。倒序提问原本是为了去除位置偏差，结果把它暴露了出来。
- 抽查 gemma 和 qwen 判为最不诚实的 8 条，它们确实是粉饰。例如“房东又涨租，这些人心都是黑的”被改成“希望我们能理解他们的难处”，不满变成了替房东说话。

### 5.2 粉饰率（Claude 标注，honesty = 0 的比例）

| | gemma4:26b | qwen2.5:7b | llama3.1:8b | 合计 |
|---|---|---|---|---|
| 开发集 | 1/14 | 6/14 | 6/14 | 13/42（31%） |
| 留出集 | 1/14 | 2/14 | 8/14 | 11/42（26%） |

改写提示词的第一条就写明“诚实是一切爱语的基础，不能粉饰”，但约四分之一到三分之一的改写仍然把说话者的不满改没了、反转了（变成自责），或者变成替对方开脱、反过来劝说说话者。这正是 PoL 把诚实放在所有爱语之首想防止的“话术美化”。按模型看，gemma 的粉饰最少。**这些数字来自 Claude 标注，需要人工复核。**

### 5.3 判官验证：原版提示词 vs 调优后（留出集，42 条）

| 维度（门槛） | 判官 | 原版 | 调优后（选中变体） |
|---|---|---|---|
| 恨语残留（ρ ≥ 0.40） | gemma | **0.47** ✓ | **0.45** ✓（anchored） |
| | qwen | −0.11 | 0.38（binary_anchored） |
| | llama | 0.29 | 0.16（binary） |
| 诚实（AUC ≥ 0.70） | gemma | **0.78** ✓ | **0.97** ✓（guided） |
| | qwen | **0.79** ✓ | 0.50（guided） |
| | llama | 0.44 | 0.52（base） |
| 流畅（ρ ≥ 0.40） | gemma | **0.42** ✓ | **0.42** ✓（binary_anchored） |
| | qwen | **0.51** ✓ | 0.37（anchored） |
| | llama | **0.47** ✓ | **0.44** ✓（base） |
| 平等联结（ρ ≥ 0.40） | 三个 | 0.67 / 0.68 / 0.66 ✓ | 0.69 / 0.67 / 0.63 ✓（base） |
| 居高临下（AUC ≥ 0.70） | gemma | **0.91** ✓ | **0.95** ✓（guided） |
| | qwen | **0.86** ✓ | **0.95** ✓（guided） |
| | llama | 0.51 | 0.60（guided） |

各变体在开发集上的得分见 `runs/flowtest/tune_report.md`。

**调优的教训**：
- 带例句的提示词确实有效：gemma 的诚实判定从 0.78 升到 0.97；居高临下维度上，gemma 从 0.91 升到 0.95，qwen 从 0.86 升到 0.95；qwen 的恨语残留从 −0.11 升到 0.38，但仍未达标。
- 但调优也会挑中噪声：qwen 的诚实判定在开发集上 guided 只比 base 高 0.01（0.77 对 0.76），留出集上却从 0.79 跌到 0.50；qwen 的流畅判定也类似（开发集 0.45 对 0.43，留出集从 0.51 跌到 0.37）。42 条样本上这么小的差距只是噪声。
- 结果是调优后，诚实维度通过的判官从 2 个变成 1 个。

### 5.4 分析结果（调优后判官，留出集准入）

| 模型 | J | 95% CI | 诚实 | 流畅 |
|---|---|---|---|---|
| gemma4:26b | 0.626 | [0.573, 0.677] | 0.889 | 0.713 |
| qwen2.5:7b | 0.398 | [0.332, 0.467] | 0.615 | 0.632 |
| llama3.1:8b | 0.314 | [0.254, 0.376] | 0.488 | 0.687 |

两两差值的置信区间都不含 0。**但这个排名不可信**：恨语残留和诚实这两个核心维度都只有 gemma 一个判官通过，gemma 给自己改写的分数没办法做自偏好校正。在 v0.2 原版提示词、双判官的条件下，诚实维度的自偏好估计为 β_self = +0.90（95% CI [0.60, 1.25]）。所以 gemma 的领先有多少来自自偏好，目前无法区分。

`pairs` 按规则拒绝产出偏好对，因为恨语残留和诚实都只有一个判官通过。

## 6. 结论

1. **工作流可用**：生成、判定、调优、验证、分析、偏好对门控全部跑通，负结果路径也验证过。
2. **判官能力**：gemma4:26b 是唯一在所有维度上都通过的判官。llama3.1:8b 不适合做中文判官。qwen2.5:7b 在量表题上有位置偏差，但在二分题上可用（原版诚实判定 AUC 0.79，居高临下 0.86–0.95）。
3. **最值得跟进的发现**：即使提示词明确要求诚实，改写仍常常粉饰原意。这需要人工标注来确认。
4. **主要瓶颈**：恨语残留维度只有 gemma 一个合格判官，而 gemma 本身也是选手。

## 7. 下一步

1. **人工标注**：用 `python run.py annotate --set holdout` 生成一批新的留出集，由 Shenton 和 Aranna 独立标注。这批人工标注同时也是检验 v0.4 的新留出集。
2. **v0.4 选择规则**：只有当某个变体在开发集上比 base 高出至少 0.05 时才换掉 base。这条规则是看过留出集之后才提出的，因此必须用新的留出集检验。
3. **加一个不参赛的判官**：选一个不在选手之列、属于第四个家族的中文能力较好的模型，只当判官。这样恨语残留和诚实维度才可能凑够两个判官，自偏好问题也会减轻。
4. **对照条件**：用更强调诚实的改写提示词（保持第一人称、明确说出原来的不满）再生成一批改写，比较粉饰率。

## 8. 诚实条款

- 本文所有验证结论基于 Claude 标注，不是人工标注。开发集的两遍标注出自同一标注者，α（0.94–1.00）是虚高的；留出集只标了一遍。
- 42 条验证样本量小，ρ 的 95% CI 宽约 ±0.25。
- 判官宽严与自偏好的校正是线性近似，不是完整的多面 Rasch 模型。
- 结果只适用于本批 60 句和这三个模型，不能推广到“PoL 爱语改写对真实人群有效”。

## 9. 复现

```powershell
python run.py validate --run flowtest --tuned --set holdout
python run.py analyze  --run flowtest --tuned
python run.py pairs    --run flowtest --tuned
```

这三步不需要 Ollama，直接使用仓库里已有的判定数据。`analyze` 做 2000 次 bootstrap，需要几分钟；加 `--quick` 改为 200 次。
